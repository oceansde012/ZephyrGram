# Backlog: what the plugin side needs from the app

Sizes: S = under a day, M = a few days, L = a week or more. Estimates are from reading the current code (base branch `ccr-40da9ed7-07luj0`, 4.5k lines in `messenger/zephyr/plugins`).

1. **Render `CHAT_ACTION` in the chat header menu** (quick on/off of the group autoresponder) - **S**. The data side exists: `PluginMenus.getItems(TYPE_CHAT_ACTION, account, dialogId, null, fragment)` and `onClick(...)` already work. Only the consumer is missing: in `ChatActivity` add the items next to the existing `zephyr_plugins` entry (`ChatActivity.java:4533`, click at `:3981`) with ids from the plugin range (`PluginMenus.isPluginItemId`), plus the same click routing already used at `:33773`. Gaps: the Java `getItems` passes `message = null` (conditions must tolerate it), and a toggle needs a live label (re-evaluate on `PluginMenus.Listener.onMenusChanged` or when the menu opens). `PROFILE_ACTION` and `DRAWER` are the same pattern in `ProfileActivity` and the main drawer (S each, not requested).

2. **Multi-file plugins to beat the single-file limit (now 2 MiB, ADR-019; 512 KB on apps <= 0.2.4)** - **L**. The whole pipeline assumes one source string: `PluginManifest.MAX_SOURCE_BYTES` (`PluginManifest.java:32`), manifest parsed from that string, one file per plugin in `PluginManager`, one sha256 per plugin and one `size` per index version (`PluginRepository.java:180,198`, `PluginManager.java:400`). Needs a package format (zip or file list), per-file hashes in the signed index, a size budget, loading modules from the plugin dir on the Chaquopy path, update and rollback of a set of files, and a security review (path traversal, which file carries the permissions). Cheaper stopgap: compressed single file or raising the limit - **S**, but it does not scale.

3. **Inline hook** - **S (remaining)**. Already implemented on `release/0.2.4` (`on_inline_result_send`, `InlineAction`, `client.send_media`, docs `docs/plugin-inline-media.md`). Remaining: release 0.2.4 and merge it into the integration branch; device testing is **unknown**. Any new inline behaviour (for example editing the result rather than cancelling or sending as own) would be M.

4. **Memory-style client** - **S (remaining)**. Transport and `memory.style` permission are implemented on `release/0.2.4` (`d3d87f7`, `e263db4`, docs `docs/plugin-memory-style-api.md`); the server contract lives in another repository (ZephyrGram-AI). Remaining: release, device test with a real server (**unknown**), and optionally a native UI for style/facts (M).
